\subsection{Análisis de una variante arquitectónica}

La arquitectura propuesta contempla tres etapas de pipeline y plantea el
cálculo del síndrome y del vector $q$ en etapas diferentes. A partir de las
propiedades del código, en particular de la condición

\begin{equation}
    B^2 = I,
\end{equation}

se analizó una posible modificación de la arquitectura con el objetivo de
calcular ambas cantidades durante la primera etapa del pipeline, utilizando
como entrada el vector recibido $r$.

Considerando la partición del vector recibido en sus componentes $r_h$ y
$r_l$, el síndrome se calcula como

\begin{equation}
    s = r_h B + r_l.
\end{equation}

Por otro lado, dado que el vector $q$ se obtiene a partir del síndrome
mediante

\begin{equation}
    q = sB,
\end{equation}

y utilizando la propiedad $B^2 = I$, se puede expresar $q$ directamente en
función de los componentes del vector recibido:

\begin{equation}
    q = (r_h B + r_l)B
      = r_h B^2 + r_l B
      = r_h + r_l B.
\end{equation}

De esta manera, la propiedad $B^2 = I$ permite plantear una arquitectura
alternativa en la cual tanto el síndrome como el vector $q$ serían calculados
a partir de $r$ durante la primera etapa del pipeline.

Sin embargo, el análisis de la implementación requerida para esta alternativa
mostró que la modificación introducía una cantidad adicional de lógica que no
resultaba conveniente para la arquitectura propuesta. En particular, se
requerían 12 compuertas XOR adicionales, junto con la lógica necesaria para
seleccionar el cálculo correspondiente al síndrome o al vector $q$.

Considerando tanto el incremento de recursos lógicos como el aumento de la
actividad de switching y, consecuentemente, de la potencia dinámica, se
descartó esta alternativa. Por lo tanto, se mantuvo la arquitectura
originalmente propuesta, conservando el cálculo del síndrome y del vector $q$
en las etapas de pipeline inicialmente definidas.
